## 🛠️ Nexus-Edge 边缘端：详细需求列表## 1. HTTP 逆向代理与无侵入拦截需求

* 【端口监听】：启动后强行占领外部访问端口（如：:80 或 :8080），作为流量的唯一入口。
* 【透明转发】：对验证通过的合法 HTTP 请求，原封不动地通过 Go 内置的 ReverseProxy 转发给本地真实业务端口（如：:9090）。
* 【拦截响应】：对判定为超速或过载的请求，直接在代理层切断，返回 HTTP 状态码 429 Too Many Requests。
* 【自定义降级文案】：支持返回自定义的 JSON 或文本响应（例如：{"code": 429, "msg": "系统繁忙，边缘节点已启动自愈保护"}）。

## 2. 限流治理细节需求（控制哪些数据）

* 【控制粒度】：
* 全局 QPS 限流：限制该节点承载的总 HTTP 请求数（如：每秒最多 500 个请求）。
   * 接口级（URL）限流：针对特定高频或核心 API（如：POST /api/v1/pay）单独设置阈值。
* 【限流白名单机制】：
* IP 白名单：支持配置特定客户端 IP 列表（如：内网扫描仪、公司内网测试机），凡是匹配白名单的 IP，100% 绿色通道放行，不计入限流计数器，不触发自适应降级。
   * Header 白名单：支持识别特定的 HTTP 请求头（如：X-Internal-Service: true 或特定的专属 Token）进行免限流放行。

## 3. 观测采集细节需求（采集哪些数据）

* 【机器基础资源指标】（C++ 读取 /proc 解析）：
* CPU 使用率：当前节点总 CPU 百分比（float32）。
   * 内存使用率：当前物理内存占用百分比（float32）。
   * 磁盘 IO 吞吐：当前系统磁盘读写速率（单位：KB/s）。
   * 网卡流量：当前网卡的进出带宽速率（单位：KB/s）。
* 【流量防护指标】（Go 代理层实时统计）：
* 总请求次数（Total Requests）：自启动以来通过该边车的总流量。
   * 拦截次数（Blocked Requests）：因触发限流或自适应过载而被拦截的次数。
* 【业务日志增量采集】（Go 监听文件）：
* 监听目标：支持配置本地业务日志文件路径（如：/var/log/nginx/access.log）。
   * 内容清洗：支持配置关键词过滤（如：只采集包含 ERROR 或 FATAL 的日志，减少弱网传输压力）。

## 4. 弱网断点续传细节需求

* 【断网判定】：当数据上报接口或心跳隧道连续失败 3 次，立刻判定为弱网/断网状态。
* 【自适应落盘】：断网状态下，停止向内存中堆积监控指标和日志。秒级切换为向本地一个指定的 cache.db（轻量 SQLite）或结构化文本文件中顺序追加写入。设置本地缓存上限（如最多 100MB），超过后采用 FIFO（先进先出）覆盖旧数据，绝不撑爆边缘磁盘。
* 【恢复续传与背压】：网络恢复后，长连接优先复活。边缘端检测到网络转好，启动后台协程读取本地缓存，以每秒不超过 50 条的速率（中控可控背压），分批次、带时间戳地补发数据，补发完毕后清空本地缓存。

## 🎛️ Nexus-Controller 中控端：详细需求列表## 1. 单连接多路复用隧道需求

* 【主动穿透接收】：在公网固定端口（如 :9999）开启 gRPC 监听，接收来自任何地方、无公网 IP 的边缘端握手请求。
* 【单 TCP 隧道多路复用】：对每一个边缘节点，仅维持一条物理 TCP 链接。通过 gRPC 内部的多路复用，并行跑两个流：一个高优先级的控制指令流（下发策略），一个低优先级的数据接收流（收指标日志）。
* 【节点存活追踪】：维护一个在线节点内存字典。连续 15 秒没收到某个节点的心跳，将该节点状态变更为 Offline。

## 2. 限流策略管理与热推送需求

* 【策略下发（控制哪些数据）】：中控可配置并下发以下核心控制数据包到边缘端：
* Strategy_Version：策略版本号（时间戳或自增 ID）。
   * Global_Max_QPS：全局允许的最大 QPS 整数。
   * URL_Rules：接口限流规则规则字典（Key 为 URL，Value 为该 URL 的最高 QPS）。
   * IP_Whitelist：字符串数组，下发最新的 IP 白名单列表。
   * Overload_CPU_Threshold：自适应过载保护线（如设为 80%，边缘端 CPU 超 80% 自动限流打折）。
* 【推送履约机制】：策略修改后，中控顺着现有长连接直接 PUSH 下去。边缘端应用成功后会返回 Ack（回执）。中控记录该节点的策略同步状态（已同步 / 待同步）。

## 3. SQLite 数据存储与极简查询 API

* 【表结构自适应创建】：启动时自动连接本地 nexus_center.db 数据库。若表不存在，利用 ORM 自动创建：节点注册表、节点性能历史表、边缘日志归档表。
* 【写入背压保护（Worker 机制）】：中控 gRPC 收到边缘端疯狂上报的日志后，不直接写入 SQLite。先丢进 Go 的 Channel 队列，由唯一一个后台专职协程每隔 1 秒进行批量写入（gorm.CreateInBatches），开启 SQLite 的 WAL 模式，确保云端中控绝对不报数据库锁死。
* 【数据查询 HTTP API】（供前端或 Demo 展示调用）：
* GET /api/nodes：查询当前全网所有边缘节点的在线状态、软件版本、策略版本。
   * GET /api/metrics?node_id=xxx&type=cpu：查询某个节点过去 1 小时内的 CPU/内存 趋势。
   * GET /api/logs?node_id=xxx&keyword=ERROR：模糊检索某个边缘节点在断网期间续传上来的业务日志。

## 💡 建议的快速落地（MVP Demo）演练剧本
既然你的终极目标是快速出 Demo 录制视频上架程序员客栈，你可以直接对着上面这份列表，在视频里演练以下三个最震撼甲方的黄金细节：

   1. 【演示白名单与限流】：
   * 配置 QPS 为 1。用测试机 A（不在白名单）疯狂刷新，第 2 次直接被 Nexus-Edge 拦截弹出 429 自定义中文警告。
      * 把测试机 B 的 IP 加入中控的白名单列表，秒级热推送生效。测试机 B 疯狂刷新，100% 成功放行。
   2. 【演示自适应自愈】：
   * 在边缘工控机上运行一个死循环脚本（模拟 CPU 飙升到 90%）。
      * 在没有修改任何中控配置的情况下，再次访问测试机 A，发现 Nexus-Edge 极其聪明地自动把限流收紧了（比如原本 1 秒能过 5 个，现在 1 个都不让过了，页面直接变 429 保护提示）。
   3. 【演示弱网断点续传】：
   * 直接拔掉网线或强杀中控服务。
      * 在边缘端不断产生新日志和新指标，展示控制台输出：[Nexus-Edge] 网络断开，启动背压保护，5条指标及日志已成功追加存入本地缓存。
      * 重新启动中控，边缘端自动重连。中控端的 SQLite 数据库里瞬间刷出了刚才断网期间产生的所有日志。
