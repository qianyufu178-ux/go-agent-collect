## Nexus-Edge 边缘端：产品需求与核心逻辑汇总## 一、 产品角色定义（Product Persona）
Nexus-Edge 是一个专为异地分支机构、物联网边缘工控机、私有化 SaaS 交付等弱网低配场景打造的“轻量化自适应流量安检门 + 零丢失运行记录仪”。它以单二进制文件形式无侵入地部署在受控端机器上。
## 二、 核心业务需求（Core Requirements）## 1. 流量治理模块：HTTP 透明反向代理与自适应限流

* 无侵入代理：扮演轻量级 HTTP 反向代理（类似精简版 Nginx），强行占领外部服务端口（如 :80），将合格流量透明转发给本地受控业务端口（如 :9090），受控业务系统无需修改任何代码。
* 高性能限流：热点限流路径由 C++ 实现（规避 Go 的 GC 垃圾回收抖动），提供令牌桶/计数器限流，高并发下响应延迟稳定在微秒级。
* 指标自适应联动（核心亮点）：限流阈值不是死板固定的。当 C++ 观测模块发现本地机器 CPU 飙升（如 >80%）或内存危急时，内部自动动态收紧限流大闸（如阈值自动打对折），主动保护机器不崩溃；机器空闲时自动恢复。

## 2. 观测采集模块：轻量化监控与弱网断点续传

* 极低开销采集：不依赖系统 SNMP 等重型服务，由 C++ 直接读取 Linux 内核的 /proc 伪文件系统，秒级获取 CPU、内存、网卡 IO 等核心指标，常驻内存控制在 30MB 以内。
* 日志增量监听：支持对本地指定路径业务日志文件的增量监听与内容过滤。
* 断网自适应落盘（防爆盾）：网络通畅时，数据通过 gRPC 流式实时上报中控；一旦检测到断网，数据秒级切换为向本地轻量化磁盘队列顺序追加，绝不挤爆系统运行内存（防 OOM）。
* 网络恢复续传（背压控制）：网络恢复后，自动读取本地缓存补发数据，且补发速度受中控背压控制，防止瞬间大流量挤爆刚恢复的弱网带宽。

## 3. 基础调度模块：配置与生命周期

* 单二进制交付：采用双栈分层架构（Go 负责外政网络与文件，C++ 负责内政算法与内核读取），支持跨平台一键编译，无任何外部中间件依赖。
* 动态热更新：与中控维持 gRPC 长连接，限流策略与采集频率支持中控下发、本地热更新，无需重启进程。

## 三、 核心数据/流量履约逻辑（Core Logic Flow）## 1. 流量拦截与限流自愈逻辑（业务生命周期）

[外部客户端 HTTP 请求]
       │
       ▼
 1. 进入 [Nexus-Edge (监听 :80 端口)]
       │
       ├─➔ 2. 【C++ 自适应限流内核判断】
       │      ├─ 检查当前 QPS 是否超标？
       │      └─ 检查本地采集模块上报的 CPU/内存 是否过载？
       │
       ├── [未通过/过载] ──➔ 3a. Nexus-Edge 直接拦截，组装标准 HTTP 429 响应返回客户端（流量终结）。
       │
       └── [已通过/安全] ──➔ 3b. Go 代理层透明转发 (Proxy) ➔ [本地业务系统 (监听 :9090 端口)]
                                                                    │
                                   [客户端] 🖎─── [原路返回结果] ─────┘

## 2. 数据采集与断网续传逻辑（运维生命周期）

[C++ 定时读取 /proc] & [Go 监听日志文件]
       │
       ▼
 1. 汇聚为标准监控数据
       │
       ├─➔ 2. 【网络状态嗅探】
       │
       ├── [网络正常] ──➔ 3a. 走 gRPC 隧道流式主动 Push ➔ [Nexus-Controller 中控端]
       │
       └── [网络断开] ──➔ 3b. 触发背压保护，数据改写向【本地磁盘队列文件 (追加存储)】
                               │
                               ▼ (网络重新连接成功)
                          4. 启动【断点续传】，限速分批补发本地缓存，发送成功后清空本地队列。
